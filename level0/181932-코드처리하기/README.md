# 코드 처리하기

## 왜 어려웠나 (헷갈렸던 부분)

- **삽질 포인트 1: `if`를 두 개 나란히 써서, mode가 같은 반복 안에서 원상복구됨**
  → `elif`가 아니라 `if`를 두 번 따로 쓰면, 첫 번째 if를 실행한 직후 바로 이어서 두 번째 if도 검사함. 그래서 `code[idx]=="1"`을 만나는 순간 mode가 0→1로 바뀌자마자, 곧바로 `if mode==1:` 블록도 검사되면서 다시 0으로 되돌아가버림. 같은 idx 한 번 반복 안에서 mode가 0→1→0으로 왔다갔다 하고, `print(mode)`를 찍어봐도 항상 0만 보여서 원인을 한참 못 찾음.

- **삽질 포인트 2: 문제 지문의 "-1"을 코드에도 그대로 넣어버림**
  → 지문의 "0부터 code의 길이-1까지"는 "전부 포함해서 돌아라"라는 자연어 표현인데, 파이썬 `range(n)`은 이미 "0부터 n 미만까지"라는 규칙을 갖고 있음. `range(len(code)-1)`이라고 쓰면 이중으로 하나가 더 빠져서, 마지막 인덱스(마지막 글자)가 통째로 검사에서 누락됨.

- **삽질 포인트 3: `mode == 1` (비교) vs `mode = 1` (대입), 등호 하나 빠짐**
  → `if code[idx]=="1": mode == 1`이라고 써서, "mode에 1을 저장"하려던 게 아니라 "mode가 1인지 비교"만 하고 결과를 버림. `mode == 1`은 문법적으로 완전히 멀쩡한 코드라서 에러가 안 나고, 조용히 mode가 안 바뀐 채로 프로그램이 계속 돌아가서 더 찾기 어려운 버그였음.

## 배운 점

- **"상태값(mode)을 바꾸는 코드"와 "그 상태값에 따라 분기하는 if"가 같이 있으면, 반드시 `elif`로 묶어야 한다.** `if`를 나란히 두 개 쓰면 위에서 바뀐 값을 아래 `if`가 곧바로 다시 확인해버림.
- **문제 지문의 "0부터 길이-1까지"는 파이썬으로 옮기면 그냥 `range(len(...))`.** 지문의 "-1"이라는 숫자를 코드에도 그대로 옮겨 적으면 안 됨 — "몇 번 반복해야 하는지" 먼저 세어보고 `range(그 개수)`로 바로 매칭시키는 습관을 들이자.
- **`==`(비교)와 `=`(대입)을 헷갈리면 에러조차 안 나는 경우가 있다.** 상태값을 "바꾸는" 코드를 짤 때는 항상 `=` 하나인지 다시 확인하는 습관을 들이자.
- 디버깅할 땐 `print(f"idx={idx}, mode={mode}")`처럼 매 반복마다 상태를 다 찍어보는 게 결과만 보고 추측하는 것보다 훨씬 확실하다.

## 최종 풀이
```python
def solution(code):
    answer = ''
    mode = 0
    for idx in range(len(code)):

        if mode == 0:
            if code[idx] != "1" and idx % 2 == 0:
                answer = answer + code[idx]
            if code[idx] == "1":
                mode = 1

        elif mode == 1:
            if code[idx] != "1" and idx % 2 == 1:
                answer = answer + code[idx]
            if code[idx] == "1":
                mode = 0

    if len(answer) == 0:
        answer = "EMPTY"
    return answer
```
